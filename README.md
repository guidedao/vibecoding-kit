# vibecoding-kit

Учебный набор курса «Вайбкодинг» от GuideDAO. Здесь лежат папки для практик:
в каждой — задание, учебный проект и автопроверка.

Писать код руками не нужно. Вы работаете через кодинг-агента (Codex или
Claude Code): открываете в нём папку практики, ставите задачу словами и
просите агента запускать команды. Автопроверка показывает, что уже готово,
а что нет.

проходите их по порядку.

## Что нужно

- **Node.js 22 или новее.** Проверить: `node -v`. Если версия ниже,
  установите актуальную LTS с nodejs.org.
- **Git 2.30 или новее.** Проверить: `git --version`. Для `17-trap` нужен
  Git 2.36 или новее.

Чего ещё потребует практика, сказано в её README. Коротко:

- `npm install` в учебном проекте ставит его зависимости (Vite, клиент
  Supabase, Playwright и другие). Сеть нужна один раз на практику.
- В `09-tracker-tests`, `10-page-audit`, `11-export-import`, `12-supabase`,
  `15-deploy` и `16-ci` тесты идут в браузере:
  `npx playwright install chromium` скачивает его один раз. Версия
  Playwright во всех практиках одна, второй раз браузер не скачивается.
- Практики до 11 работают без внешних сервисов и ключей. С практики 12
  нужен ваш бесплатный проект Supabase: адрес и ключи вы вписываете сами в
  `.env.local` учебного проекта, в набор они не попадают. В `14-crypto-pro`
  и `18-ai-tip` нужен Supabase CLI, в 14 — ещё тестовый кошелёк в сети
  Base Sepolia.
- `15-deploy` и `16-ci`: аккаунты GitHub и Vercel; для 16 — GitHub CLI
  2.87 или новее.
- `17-trap`: gitleaks 8.19 или новее.
- `18-ai-tip`: ключ провайдера модели нужен только для живого прогона по
  желанию, автопроверка работает без сети и без ключа.
- `19-legacy`: сеть для `npm ci` и `npm install`.

## Как начать

1. Скачайте набор один раз:

   ```bash
   git clone https://github.com/guidedao/vibecoding-kit
   ```

2. Перейдите в папку нужной практики, например:

   ```bash
   cd vibecoding-kit/04-broken-test
   ```

3. Откройте эту папку в агенте и попросите выполнить `npm run setup`.
   Команда развернёт учебный проект в папке `tracker` — это отдельный
   Git-репозиторий со своей историей. Начните новую сессию агента в папке
   `tracker` и дальше следуйте уроку на платформе и `README.md` практики.
   Исключения: в `19-legacy` проект называется `journal`, а `17-trap`
   создаёт приманку вне набора, в `~/trap-17`.

Если набор обновился, скачайте изменения командой `git pull` в папке
`vibecoding-kit`. Ваши папки `tracker` при этом не меняются.

## Что делает `npm run check`

Автопроверка обычно запускается в папке `tracker` практики. В `17-trap` и
`19-legacy` — в папке самой практики, как сказано в их README. Проверка
смотрит на результат по списку критериев и печатает по каждому строку с
отметкой:

```text
✔ критерий выполнен
✘ критерий не выполнен
  Подсказка: куда смотреть.

Итог: 5 из 6. Практика не пройдена.
```

Так выглядит вывод в практиках модуля 7. С практики 10 критерии
нумерованы, а у непройденного есть строки «Что не так» и «Подсказка»:

```text
2. Привычка видна в другом браузере
   Пройдено: нет
   Что не так: …
   Подсказка: …

Итог: пройдено 8 из 9.
```

В `19-legacy` строка критерия короче: «2. Название: да» или «нет».
Практики, где проверка портит код и смотрит, заметят ли это тесты
(`04-broken-test`, `09-tracker-tests`), печатают по каждой поломке «Тест
ловит поломку: да/нет» или «Поймана: да/нет». Формат описан в уроке.

Код завершения: `0` — всё готово, `1` — есть невыполненные критерии,
`2` — проверку нельзя провести, например проект не запускается или тестов
ещё нет, `3` — сбой самой проверки. Проверка не меняет ваш проект: всё, что
ей нужно испортить или собрать, она делает во временной копии.

## Если проверка падает

1. Прочитайте подсказку под строкой с ✘ или «нет». Она говорит, куда
   смотреть.
2. Покажите вывод агенту и попросите объяснить, что именно не выполнено.
   Просите сначала найти причину, а потом чинить.
3. Не правьте файлы проверки в `checks/` и не ослабляйте тесты, чтобы
   проверка прошла. Чинится код, а не проверка.
4. Запустите проверку снова.

Если после итога появились строки `npm error ...`, это npm сообщает, что
команда завершилась с ненулевым кодом. Ошибки в наборе они не означают.

Если проверка не запускается совсем:

- `node -v` показывает версию ниже 22 — обновите Node.js;
- `git --version` выдаёт ошибку — установите Git;
- проверка просит выполнить `npm run setup` — выполните его в папке
  практики;
- проверка просит выполнить `npm install` — выполните его в папке
  `tracker`;
- хочется начать практику заново — переименуйте или удалите папку
  `tracker` и снова выполните `npm run setup`.

Если всё равно не получается, принесите вывод команды в чат курса.
