# 07 · Слияние двух веток

Практика модуля 7 «Терминал и Git» курса «Вайбкодинг». Полное задание с
шагами — в уроке «Слияние двух веток» на платформе GuideDAO. Здесь коротко:
как подготовить учебный проект и как понять, что практика готова.

## О чём практика

Учебная копия трекера привычек с веткой `main` и двумя ветками фич:
`rename-habit` (переименование привычки) и `habit-emoji` (значок перед
названием). Обе ветки меняют одну и ту же функцию. Нужно слить их в `main`,
разобрать конфликт так, чтобы работали обе фичи, и завершить слияние. Ваш
собственный трекер в этой практике не меняется.

## Подготовка

Нужны Node.js 22 или новее и Git 2.23 или новее. Пакеты ставить не нужно,
`npm install` не нужен.

1. Откройте эту папку (`07-merge-conflict`) в агенте и попросите выполнить:

   ```bash
   npm run setup
   ```

2. Появится папка `tracker` — отдельный Git-репозиторий с ветками `main`,
   `rename-habit` и `habit-emoji`. Начните новую сессию агента в папке
   `07-merge-conflict/tracker` и дальше работайте только в ней.

Если в Git на вашем компьютере не задано имя автора, `npm run setup` подпишет
коммиты в учебной папке именем «Студент» и скажет об этом.

Команды в папке `tracker`:

| Команда | Что делает |
| --- | --- |
| `npm test` | запускает тесты |
| `npm run check` | автопроверка: смотрит историю, файлы и тесты |
| `npx serve .` | открывает приложение в браузере, остановка — Ctrl+C (при первом запуске npx скачает пакет `serve`) |

## Когда практика готова

`npm run check` выводит девять строк с отметкой ✔ и итог
«Итог: 9 из 9. Практика пройдена.» Порядок, в котором вы вливаете ветки,
не важен.

## Начать заново

- Запутались посреди слияния: `git merge --abort` вернёт `main` к состоянию
  до него.
- Начать всё сначала: переименуйте или удалите папку `tracker` и снова
  выполните `npm run setup`.

## Если что-то не так

- **«Слияние не завершено».** В файлах остались конфликты или слияние не
  закоммичено. `git status` покажет, что осталось.
- **«остался маркер конфликта».** В файле остались строки `<<<<<<<`,
  `=======` или `>>>>>>>`. `git diff --check` покажет все.
- **«Тесты … изменены».** Конфликт разрешают в коде, файлы тестов веток не
  меняют.
- **После итога появились строки `npm error ...`.** Некоторые версии npm так
  сообщают, что проверка не пройдена. Ошибки в самом наборе здесь нет.
